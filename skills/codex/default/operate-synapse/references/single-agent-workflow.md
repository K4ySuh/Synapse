# Single-Agent Workflow

Use this workflow for direct work and durable work owned by the same Codex
agent across context changes or restarts.

## Recover

1. Identify the operator-selected workspace and exact authorized target.
2. Query the smallest revision-aware context that preserves the objective.
3. Inspect active, approval-pending, incomplete, or outcome-unknown jobs,
   operations, and work-execution attempts before planning new effects.
4. Inspect relevant durable work. Continue an applicable item or stay direct;
   do not create a coordination tree simply because the objective has phases.
5. Discover selected capabilities and their live contracts before depending on
   an action name, schema, effect, provider, or availability assumption.

## Execute and preserve progress

- Prefer passive workspace evidence and local analysis before traffic.
- Before consequential execution, establish exact target, effect, risk,
  credential reference, output, scope result, and server-held authority result.
- Link long-running or consequential execution to durable work when restart
  recovery materially benefits. Preserve every returned job, action, evidence,
  artifact, and operation reference.
- Update concise facts, negative results, blockers, contradictions, open gaps,
  last-seen revision, and next safe work. Never persist reasoning traces.
- On timeout, client loss, or expired lease, reconcile the same execution. Do
  not infer failure and do not redispatch active or outcome-unknown work.

## Change methodology without losing state

When moving between `$synapse-web-pentesting` and
`$synapse-cve-intelligence`, retain:

- workspace and current revision;
- exact target and authorization boundaries;
- action, job, observation, evidence, artifact, and work references;
- normalized component/version and route/auth context;
- candidates, contradictions, negative results, open gaps, and next decisions.

This is one agent changing methods, not a delegation or handoff. Record a
durable checkpoint only when it helps recovery or another independent consumer.
Accepted methodology analysis records the selected package ID and digest in
`methodRef`; keep that attribution and its contribution receipt across the
transition. For explicit examples, restart recovery, and missing-package or
digest-mismatch remedies, read the Web Pentesting
`references/selection-and-resumption.md` guide from the installed default
profile or hosted guidance catalog.

## Converge

Render reports from canonical workspace entities and evidence. Separate
confirmed findings, unreviewed candidates, negative results, contradictions,
blocked or incomplete coverage, active/unknown execution, and recommendations.
Complete durable work only when its contract is met; otherwise block, replan,
or leave an explicit next step without manufacturing success.
